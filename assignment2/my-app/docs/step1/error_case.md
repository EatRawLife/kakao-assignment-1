# Step 1 — 에러 케이스

## EC1-01: 빈 입력 제출

| 항목 | 내용 |
|------|------|
| **상황** | 입력창이 비어 있거나 공백 문자만 입력한 상태에서 Enter 또는 추가 버튼 클릭 |
| **원인** | `inputValue.trim() === ''` |
| **처리** | - 할 일 목록에 항목을 추가하지 않는다 <br> - 입력창 아래에 인라인 에러 메시지를 표시한다 <br> - 입력창에 포커스를 돌려준다 |
| **에러 메시지** | `"할 일을 입력해주세요."` |
| **관련 상태** | `hasError: true` |

```
[입력창]
[에러 메시지: "할 일을 입력해주세요."]  ← EC1-01 발생 시 노출
```

---

## EC1-02: 에러 상태 자동 해제

| 항목 | 내용 |
|------|------|
| **상황** | EC1-01 에러가 표시된 상태에서 사용자가 입력을 시작함 |
| **조건** | `inputValue.trim() !== ''` |
| **처리** | 에러 메시지를 즉시 숨긴다 (`hasError: false`) |
| **구현 포인트** | `onChange` 핸들러에서 `inputValue` 변경 시 `hasError`를 초기화 |

---

## 에러 상태 흐름 요약

```
사용자 입력 없이 제출
      ↓
hasError = true  →  에러 메시지 표시, 입력창 포커스
      ↓
사용자가 타이핑 시작 (onChange)
      ↓
hasError = false  →  에러 메시지 사라짐
      ↓
유효한 텍스트로 재제출
      ↓
항목 추가 성공, 입력창 초기화
```

## EC1-03: 인라인 수정 중 빈 값 확정 시도

| 항목 | 내용 |
|------|------|
| **상황** | 수정 모드에서 input을 비우거나 공백만 남긴 상태로 Enter 또는 저장 버튼 클릭 |
| **원인** | `editValue.trim() === ''` |
| **처리** | - 수정을 확정하지 않는다 <br> - 수정 input에 포커스를 유지한다 <br> - 수정 모드를 벗어나지 않는다 |
| **에러 메시지** | 별도 표시 없음 — 포커스 유지로 의도를 전달 |

---

## EC1-04: 수정 모드 중복 진입 방지

| 항목 | 내용 |
|------|------|
| **상황** | 이미 수정 모드인 항목에서 수정 버튼을 다시 클릭하는 경우 |
| **처리** | 이미 수정 중인 상태이므로 별도 동작 없음. `isEditing` 상태로 버튼 또는 input 렌더링을 분기해 중복 진입 자체를 막는다 |
| **구현 포인트** | `TodoItem`의 `isEditing` 로컬 state로 수정 모드를 관리. 수정 중일 때는 수정 버튼 대신 저장 버튼을 렌더링 |

---

## 구현 시 주의사항

- 에러 메시지는 조건부 렌더링으로 처리한다. `display: none`이 아닌 JSX의 `&&` 또는 삼항 연산자를 사용한다.
- 에러 상태(`hasError`)는 `TodoInput` 컴포넌트의 **로컬 state**로 관리한다. 상위 컴포넌트까지 끌어올리지 않아도 된다.
- 에러 표시 중에도 입력창은 수정 가능 상태를 유지한다.
- 수정 모드 상태(`isEditing`)는 `TodoItem` 컴포넌트의 **로컬 state**로 관리한다.
