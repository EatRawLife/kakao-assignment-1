# Step 1 — 비기능 명세

## 코드 품질

| # | 요구사항 | 기준 |
|---|---------|------|
| NF1-01 | 파일 분리 | 컴포넌트별로 독립 파일 작성. `App.jsx`, `TodoInput.jsx`, `TodoList.jsx`, `TodoItem.jsx` 각각 분리 |
| NF1-02 | 주석 | 모든 컴포넌트·상태·핸들러·JSX 블록에 역할 설명 주석 필수 (교육용 코드) |
| NF1-03 | props 방어 | 모든 컴포넌트의 props에 default parameter 설정 (예: `onDeleteTodo = () => {}`) |
| NF1-04 | 입력 검증 | 사용자 입력은 `trim()` 후 빈 문자열인지 반드시 검사 |
| NF1-05 | 배열 가드 | `todoList.map()` 전에 `Array.isArray(todoList)` 확인 |
| NF1-06 | 명명 규칙 | 핸들러는 `handle` 접두사, boolean은 `is`/`has`/`can` 접두사 준수 |

## 디자인 / UX

| # | 요구사항 | 기준 |
|---|---------|------|
| NF1-07 | 반응형 | 모바일(320px) ~ 데스크톱(1280px) 범위에서 레이아웃이 무너지지 않아야 한다 |
| NF1-08 | 메인 컬러 | 버튼·포커스 링 등 primary 색상은 `#672be0` 사용 |
| NF1-09 | 빈 상태 표시 | 할 일 목록이 비어 있을 때 안내 메시지를 표시한다 |
| NF1-10 | 입력창 포커스 | 페이지 로드 시 또는 항목 추가 후 입력창에 포커스가 자동으로 맞춰진다 |
